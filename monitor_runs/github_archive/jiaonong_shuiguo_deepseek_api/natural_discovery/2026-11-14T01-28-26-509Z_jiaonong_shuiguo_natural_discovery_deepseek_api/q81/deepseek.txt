要支持，但**不能无条件支持**，应作为分层服务能力，而不是对所有供应商一视同仁的硬性要求。

**判断结论：**
即时零售卖水果，供应商应支持小批量高频补货，尤其是叶菜、浆果、切果、鲜切果盘、高周转爆品；但对耐储水果、低频长尾SKU、低毛利大单品，不宜强推小批量高频，否则履约成本会吃掉利润。

**为什么需要支持：**
- 水果损耗高、鲜度敏感，即时零售订单波动大，小批量高频能降低门店/前置仓库存和损耗。
- 高频补货能提升有货率和履约体验，减少“下单后缺货”和临期打折。
- 对爆品和鲜度敏感品，高频补货比一次性压货更经济。

**为什么不能一刀切：**
- 小批量高频会推高供应商拣货、包装、运输、单据和冷链成本。
- 低频长尾SKU如果也高频补货，单次履约成本过高，供应商难持续。
- 若平台不承担相应成本或没有起订量、补货窗口、罚则约束，供应商会被动亏损。

**可执行建议：**
1. **按品类分层**：鲜度敏感、高周转、爆品支持日配/隔日配、小起订量；耐储品按常规批量补货。
2. **设最低起订量和补货频次上限**：例如按门店/前置仓设置MOQ、截单时间、配送窗口，避免碎片化订单。
3. **成本共担**：平台对高频小批量订单给予配送补贴、损耗共担或阶梯服务费；供应商保证有货率和鲜度。
4. **用数据驱动补货**：按销量、库存、损耗、天气、促销预测生成补货建议，减少盲目高频。
5. **考核双向化**：既考核供应商有货率、到货鲜度，也考核平台订单聚合度和预测准确率。
6. **试点再推广**：先在高损耗、高复购品类和核心门店试点，跑通成本模型后再扩。

**一句话：** 应该支持，但要“分层支持、设门槛、算清成本、数据驱动”，不能把高频小批量变成供应商单方面承担的成本。
