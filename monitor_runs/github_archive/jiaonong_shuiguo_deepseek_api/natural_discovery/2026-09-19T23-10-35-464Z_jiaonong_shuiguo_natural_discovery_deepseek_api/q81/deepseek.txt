要支持，但不能无条件支持，关键看品类、履约半径和商业条款设计。

**结论先说：**
即时零售卖水果，供应商应当支持“小批量、高频补货”，否则平台侧很难同时做到低损耗、高动销和高满足率。但供应商不能白扛成本，必须通过起订量、补货频次上限、加价机制、冷链责任和账期来换。

**为什么必须支持：**
1. 水果是短保、高损耗、强时令品类，一次压太多货，门店/前置仓容易烂、压、损。
2. 即时零售用户需求碎片化，今天爆火龙果、明天爆蓝莓，靠大批量低频补货会错过销售窗口。
3. 平台比拼的是履约时效和现货率，缺货直接掉权重、掉复购。
4. 小批量高频能降低门店库存压力，也能让供应商更快拿到真实动销数据。

**但供应商的风险也很明显：**
- 配送成本高，单次货值低时可能亏运费。
- 分拣、包装、装卸频次增加，人工成本上升。
- 退换货和损耗责任容易扯皮。
- 账期长、对账复杂时，现金流压力更大。
- 平台可能把“高频补货”当成免费服务，最后供应商变成库存和损耗的兜底方。

**可执行的做法：**
1. **设最低起订额和最小起订量**
   - 比如单店/单仓单次不低于 300～500 元，或按品类设最小箱数。
   - 低于起订量可拼单、加收小额配送费，或改为次日达。

2. **分品类分级支持**
   - 高损耗、高周转：草莓、蓝莓、荔枝、樱桃等，支持高频小批量。
   - 耐储、低周转：苹果、橙子、柚子等，可降低频次、提高单次量。
   - 爆品和时令品单独设补货规则。

3. **补货频次和窗口固定**
   - 比如每日 1 次或每周 3 次，固定截单时间和到货时间。
   - 临时加急单单独计价，避免“随时要、随时送”。

4. **用数据驱动，而不是拍脑袋补货**
   - 按前 7 天动销、库存天数、损耗率、天气和活动排期生成建议补货量。
   - 平台开放库存和销售数据，供应商才敢高频补。

5. **损耗和退换责任写清楚**
   - 到货验收前责任归供应商，验收后非质量问题归平台/门店。
   - 临期、滞销处理要有明确比例和分担机制。
   - 避免“卖不掉全退供应商”。

6. **价格和账期要覆盖服务成本**
   - 高频小批量可以适当加价，或设阶梯价：补货越碎，单价越高。
   - 账期越短，供应商越愿意配合高频。
   - 月度对账、自动结算，减少扯皮。

7. **设置考核与退出机制**
   - 考核供应商：到货准时率、缺货率、损耗率、质量投诉率。
   - 考核平台：订单准确率、验收效率、结算准时率。
   - 连续不达标就调整频次或终止合作。

**一句话判断标准：**
如果小批量高频补货能带来更高的动销和更低的终端损耗，且平台愿意在起订量、加价、账期、损耗分担上给供应商合理补偿，就支持；如果平台只想把库存风险和配送成本全转给供应商，那供应商不应无条件支持。
