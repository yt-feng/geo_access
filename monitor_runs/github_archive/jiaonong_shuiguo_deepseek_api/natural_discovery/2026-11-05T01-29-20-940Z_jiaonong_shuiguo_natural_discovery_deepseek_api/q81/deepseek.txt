要支持，但应设门槛和价格机制，不能无条件做。

**判断依据**
水果在即时零售里是典型的高损耗、短保鲜、需求波动大的品类：门店/前置仓面积小、库存天数短，消费者对新鲜度和缺货都敏感。供应商如果只支持大批量低频补货，平台端要么缺货丢单，要么压库损耗，最终会反噬供应商的退货率和结算。因此小批量高频补货是方向。

**但供应商不能直接无条件接，建议这样设计：**

1. **设最小起订量和补货频次上限**  
   例如单SKU单次不低于X箱、每日最多补1—2次；低于门槛走“拼单补货”或次日达，不承诺即时。

2. **分层服务、分层价格**  
   高频小批量补货加收配送/分拣费，或把价格上浮3%—8%；大批量常规补货给底价。让平台按真实成本选择，而不是把成本全压给供应商。

3. **只对高周转SKU开放高频补货**  
   香蕉、苹果、柑橘、应季爆品等动销快的做高频；礼盒、低频小众果品走批量。用销量分级管理，不搞全品类一视同仁。

4. **信息共享换承诺**  
   平台提供次日销量预测、库存可视、缺货率数据；供应商据此备货。平台对高频补货SKU给最低采购量承诺或滞销分担，否则供应商承担全部损耗风险不划算。

5. **明确损耗和退货责任**  
   到店验收标准、损耗归属、临期处理规则写进协议。高频补货最容易扯皮的是“补了卖不掉谁承担”，必须提前定。

6. **用区域集单和前置分拨降成本**  
   同一区域多门店合并订单、供应商在区域设周转仓、平台自提或共同配送，把“高频小批量”的物流成本摊薄，而不是让供应商单车小批量直送。

**结论**：供应商应支持小批量高频补货，但必须是“有门槛、有价差、有数据、有责任划分”的支持。无条件支持会做成亏损服务；完全不支持会失去即时零售的水果份额。建议先选10—20个高动销SKU试点，跑通补货频次、损耗率和履约成本后再扩。
