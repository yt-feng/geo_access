评估水果供应商的仓配覆盖，核心不是看他“能发全国”，而是看他能否在**门店需要的时效和损耗约束内，稳定送到每个城市和门店**。建议按下面框架做。

## 1. 先明确评估口径
不要只用“供应商有几个仓”判断，先定义业务约束：

- **时效要求**：叶菜/浆果/现切水果是否要求次日达、当日达、定时达
- **温区要求**：常温、冷藏、冷冻；水果多为冷藏+常温混配
- **起送门槛**：单店起送量、单城起送量、最低配送频次
- **验收标准**：到货温度、破损率、成熟度、农残检测、批次追溯
- **门店分布**：按城市、商圈、仓到店距离、门店密度分层

这些约束决定了“覆盖”是有效覆盖还是名义覆盖。

## 2. 评估供应商仓配网络
重点看四层：

**① 仓网布局**
- 每个城市或区域是否有自营仓、合作仓、中转仓
- 仓到门店的直线/实际配送半径
- 仓的温区能力：冷藏库容、分拣能力、越库能力
- 是否支持多温区共配，避免水果和冻品混装

**② 配送能力**
- 干线：产地/总仓到城市仓的频次、时效、温控
- 城配：城市仓到门店的车辆、线路、频次、送达时段
- 是否自营车队或稳定外包；旺季/节假日运力保障
- 是否支持拆零、多批次、小批量高频配送

**③ 时效与履约**
- 按城市逐店测算：下单截止时间 → 分拣 → 发车 → 到店时间
- 看历史履约数据：准时率、缺货率、破损率、温控异常率
- 异常处理：退换货时效、门店拒收后的补送能力

**④ 信息化与追溯**
- 订单、库存、在途温度是否可实时查看
- 批次追溯能否到门店
- 是否支持门店收货扫码、异常拍照上传

## 3. 做“城市-门店”覆盖矩阵
建议按城市建表，每个城市填：

| 城市 | 门店数 | 供应商仓距离 | 配送频次 | 最晚下单 | 到店时效 | 温区能力 | 起送量 | 履约准时率 | 破损率 | 是否有效覆盖 |
|---|---|---|---|---|---|---|---|---|---|---|

判断规则：
- **有效覆盖**：能按门店要求时效、温区、频次稳定送达，且起送量可接受
- **有条件覆盖**：需要合并订单、提高起送量或降低频次
- **名义覆盖**：供应商说能送，但时效/温控/成本不满足
- **未覆盖**：需中转、第三方或门店自提

## 4. 重点评估水果品类差异
不同水果对仓配要求不同，不能一刀切：

- **高损耗短保**：浆果、荔枝、水蜜桃、现切果——要求短链路、冷藏、高频少批量
- **耐储水果**：苹果、橙、梨——可接受区域仓+较低频次
- **催熟类**：香蕉、芒果——要评估催熟仓和成熟度管理
- **产地直发**：大单品可产地直发城市仓，但要评估干线温控和到仓损耗

## 5. 用试运行验证
纸面评估后，选**3类城市**试跑：
- 核心高密度城市
- 远距离低密度城市
- 旺季/节假日压力场景

试跑2—4周，记录：准时率、到货温度合格率、损耗率、缺货率、门店投诉率、单店配送成本。只有试跑数据能证明“覆盖”是否成立。

## 6. 最终判断标准
一个供应商的仓配覆盖是否合格，建议同时满足：

1. 目标城市中**有效覆盖率≥80%**，其余有明确补网计划
2. 核心城市支持**次日达或当日达**，且到店时间窗可承诺
3. 冷藏水果全程温控可追溯，到货温度合格率≥98%
4. 门店起送量不导致单店库存积压或频次不足
5. 旺季运力有书面保障方案
6. 履约数据可对接，异常可在24小时内闭环

## 可执行结论
先让供应商按“城市-门店-品类-时效-温区-起送量”提供仓配覆盖表，再用你的门店订单数据做匹配，筛出名义覆盖和未覆盖门店；最后用试运行数据决定是否签约或要求补仓。**不要只看仓的数量，要看到店时效、温控和门店级履约数据。**
