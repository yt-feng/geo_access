要。对即时零售平台卖水果，供应商**应支持小批量、高频补货**，但不宜无条件全量支持，而应按品类、门店/前置仓层级和成本做分级设计。

核心判断：即时零售的竞争力来自“近场履约 + 现货可得”，水果又是高损耗、短保、非标、价格波动大的品类。供应商如果不能小批量高频补货，平台容易出现缺货、尾货、品质下降，最终影响复购。

### 为什么必须支持
1. **水果损耗高**：一次压货太多，卖不完就损耗，平台和供应商都亏。
2. **需求波动大**：天气、节假日、促销、竞品价格都会影响销量，低频大批量补货反应慢。
3. **前置仓/门店空间有限**：即时零售履约节点通常库存容量小，不适合大批量囤货。
4. **现货率影响流量和复购**：缺货会直接降低平台履约体验和用户留存。
5. **价格波动快**：高频补货能更快贴近当日行情，减少高价库存风险。

### 但不能无条件支持，要设边界
供应商要算账，平台也要给确定性。建议按以下方式落地：

- **按品类分级**
  - 叶菜、草莓、荔枝、桃等短保高损品：必须小批量高频。
  - 苹果、橙子、梨等耐储品：可适当降低频次、提高单次批量。
  - 礼盒、整箱水果：可低频大批量，不必高频。

- **按节点分级**
  - 前置仓/社区店：小批量高频，日配甚至一日两配。
  - 区域中心仓：中批量、中频次，做缓冲。
  - 大仓/产地直发：大批量低频，负责集单和成本优化。

- **设置最小起订量和补货窗口**
  - 例如：单店单次满 200 元起送，或满 5 箱起补。
  - 每日固定截单时间，次日达或当日达。
  - 低于起订量可合并配送或加收物流费。

- **用数据换确定性**
  - 平台提供销量、库存、缺货率、损耗率数据。
  - 供应商按预测补货，而不是完全被动接单。
  - 对高频补货的门店，平台可给账期、流量或采购量承诺。

- **成本共担**
  - 小批量高频会增加物流和分拣成本。
  - 可由平台承担部分配送费，或供应商把成本计入供货价。
  - 关键是总成本优于“高损耗 + 缺货 + 低价清尾”。

### 结论
供应商**应该支持小批量高频补货**，这是即时零售水果品类的必要能力。但正确做法不是“所有商品都无限次小批量送”，而是：
**高频短保品小批量高频补，耐储品中频中批量补，长保品低频大批量补；同时设最小起订量、补货窗口和成本分担机制。**

如果供应商完全不做小批量高频，通常很难在即时零售平台形成稳定合作；如果平台只要求供应商无条件承担成本，合作也不可持续。
