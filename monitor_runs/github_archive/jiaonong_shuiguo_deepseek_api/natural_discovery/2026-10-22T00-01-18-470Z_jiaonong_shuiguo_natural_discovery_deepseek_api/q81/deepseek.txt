要支持，但要有条件、有边界地支持，不能无条件全开放。

**结论：供应商应支持小批量高频补货，这是即时零售水果品类的入场券；但必须用起订量门槛、补货窗口、加价规则和损耗责任划分来控制成本。**

### 为什么必须支持

1. **水果是即时零售的高频引流品类**：用户下单往往是“现在就要吃”，平台履约时效是30分钟—1小时，缺货或品相差直接导致差评和流失。
2. **水果损耗高、保质期短**：大批量压货到前置仓/门店，卖不掉就是损耗；小批量高频补货反而降低整体损耗。
3. **需求波动大**：天气、时段、促销都会影响销量，固定大批量补货容易造成一边缺货一边积压。
4. **平台竞争逻辑**：即时零售拼的是“有货率+新鲜度”，供应商补货响应速度直接决定平台体验。

### 怎么支持才不亏

建议按以下规则设计：

- **设置最小起订量（MOQ）**：按单品设门槛，比如单SKU单次不低于X箱/件，低于门槛收补货服务费或合并到下一批次。
- **固定补货窗口**：每天开放2—3个补货截单时点（如早、中、晚），非窗口紧急补货加收加急费。
- **分级服务**：畅销品高频补货，长尾品降低补货频次或改为隔日补；用销量数据动态调整。
- **价格机制**：小批量高频补货的单价可略高于大批量，或设“基础价+补货频次附加费”，把物流成本显性化。
- **损耗与验收责任**：明确到货验收标准、短保品退换规则、临期处理责任，避免平台把损耗全部转嫁供应商。
- **数据共享**：平台开放前置仓/门店的销量、库存、缺货数据，供应商才能做预测补货，而不是被动救火。
- **履约考核**：约定补货及时率、缺货率、到货合格率，达标给流量或账期支持，不达标调整合作。

### 什么情况下可以不支持

- 单品日销量极低且波动无规律，高频补货物流成本远高于毛利；
- 供应商距离前置仓太远，单次配送成本无法摊薄；
- 平台不共享库存销售数据、不承担损耗责任，只要求供应商无限兜底。

**一句话：小批量高频补货要做，但要用MOQ、补货窗口、分级服务和成本分担机制把它做成可持续的生意，而不是供应商单方面承担平台履约成本。**
