要支持，但要“有条件地支持”，不能无差别开放。

**结论：即时零售平台卖水果，供应商应支持小批量高频补货，但必须设门槛、算清账、分品类分级。**

**一、为什么必须支持**

1. **水果是即时零售的核心引流品类**，用户对新鲜度、缺货率极其敏感，断货直接掉复购。
2. **水果损耗高、保质期短**，大批量压货到门店/前置仓会烂在仓里，小批量高频反而降低整体损耗。
3. **平台履约逻辑要求“近场快反”**，前置仓SKU浅、库存浅，供应商不配合高频补货，平台只能靠加价或换供应商解决。
4. 不支持高频补货的供应商，在平台侧会被标记为“履约能力弱”，长期拿不到流量和排面。

**二、支持的前提条件（可判断标准）**

| 条件 | 判断标准 |
|---|---|
| 起订量门槛 | 设最低起订额/起订件数，低于门槛加收配送费或合并到次日 |
| 补货频次 | 按品类定：叶菜/浆果每日1–2次；苹果/橙类2–3天一次 |
| 补货窗口 | 固定截单时间和到仓时间，超时顺延，避免无限次随叫随到 |
| 价格机制 | 小批量单价可上浮3%–8%，或设“高频补货服务费”，把成本显性化 |
| 损耗责任 | 到仓验收标准、短保品退货比例提前写清，避免高频补货变成高频退货 |
| 数据共享 | 平台开放日销、库存、缺货数据，供应商按数据补，而不是凭感觉补 |

**三、分品类策略**

- **高损耗短保品**（草莓、蓝莓、叶菜、切果）：必须高频，日配为主，小批量是刚需。
- **耐储水果**（苹果、梨、橙、瓜类）：不需要高频，2–3天一次、适度批量更经济。
- **爆款引流品**：高频+安全库存双轨，保不断货。
- **长尾小众品**：合并补货或隔日补，不单独跑高频。

**四、供应商要算的三笔账**

1. **履约成本账**：高频小批量会推高拣货、分拣、配送、交接成本，必须通过起订门槛或服务费覆盖。
2. **损耗账**：高频补货降低门店端损耗，但供应商端分拣次数增加，要对比总损耗率是否真的下降。
3. **账期与现金流账**：高频补货往往伴随高频对账，账期不清晰会拖垮现金流，合同里要约定结算周期。

**五、给供应商的可执行建议**

1. 先接**1–2个高周转品类**做高频补货试点，跑2–4周看履约成本和损耗数据。
2. 和平台谈**阶梯补货协议**：销量越高补货频次越高，但起订门槛和服务费同步明确。
3. 要求平台提供**销量预测和缺货数据接口**，用数据驱动补货，避免被动救火。
4. 设置**红线**：单日补货超过约定次数、单次金额低于门槛的，走加价或次日合并，不做无限兜底。

**一句话判断**：即时零售的水果生意，供应商不支持小批量高频补货就进不了核心供应链；但无门槛、无加价、无数据支撑地支持，就是拿自己的履约成本补贴平台的用户体验，长期必亏。支持，但要协议化、分级化、数据化。
